El proyecto

GEA gestiona activos históricos, órdenes de compra por etapas y certificación documental. Incluye verificación de certificados, comparación SHA-256 y acceso según rol y titularidad.

Plataforma: Python 3.11+, Django 5.2 LTS, MariaDB, Redis, Git, cPanel y Passenger. Dependencias: requirements.txt y uv.lock.

01 · Modelo de calidad

ISO/IEC 25010:2023

Systems and software engineering — Systems and software Quality Requirements and Evaluation (SQuaRE) — Product quality model. Segunda edición, publicada en noviembre de 2023.

Se elige porque define un modelo de características para especificar y evaluar la calidad de productos de software. La selección orienta esta evaluación; no significa que GEA esté certificada ni que cumpla por completo la norma (International Organization for Standardization [ISO], 2023).

04a · Versionado

SemVer MAYOR.MENOR.PARCHE. Versión candidata propuesta: 1.0.0. MAYOR: cambio incompatible, por ejemplo modificar el contrato de verificación pública; MENOR: nueva función compatible, como un filtro adicional en inventario; PARCHE: corrección compatible, como un error en el formato de una fecha. Etiqueta candidata; pendiente de aprobación.

La línea base incluye commit, etiqueta, requirements.txt, uv.lock, migraciones, configuración sin secretos, informe de pruebas y manifiesto de despliegue. Los secretos se conservan fuera de Git.

05b · Instalación en ocho pasos

Comandos basados en la guía aportada. Los valores entre <…> se sustituyen por los reales. Ejecutar comandos de gestión desde la raíz de GEA y con el virtualenv de cPanel activo.

  1. Preparar versión y respaldo

    En local: ejecutar suite y controles; exportar dependencias de producción. Guardar commit previo y respaldo cifrado de base, media y configuración.

    uv run python manage.py test --settings=app_core.settings_test
uv export --no-dev --format=requirements-txt > requirements.txt
uv run python manage.py check_requirements

    Verificación: Suite sin fallos; export actualizado; respaldo y restauración de prueba verificados.

  2. Crear la aplicación Python

    En cPanel, habilitar aplicación Python 3.11, raíz fuera de public_html, URL de GEA y archivo de inicio passenger_wsgi.py. Activar por SSH el virtualenv que cPanel indique.

    python --version
python -m pip --version

    Verificación: Python y pip pertenecen al virtualenv correcto. La ubicación exacta depende de la cuenta cPanel.

  3. Obtener la versión candidata

    Clonar el repositorio si no existe y seleccionar el tag aprobado. No ejecutar git pull sobre una release sin registrar versión.

    git clone https://github.com/sebasmd-projects/gea_module_0.git
cd gea_module_0
git checkout <TAG_APROBADO>
python -m pip install -r requirements.txt

    Verificación: HEAD coincide con el commit aprobado; pip termina sin errores. Sustituir TAG_APROBADO por la etiqueta real.

  4. Configurar datos y secretos

    Crear base y usuario MariaDB en cPanel, asignar privilegios a esa base. Cargar variables de docs/env.example mediante el mecanismo privado de producción.

    DJANGO_DEBUG=False
DB_ENGINE=django.db.backends.mysql
DB_HOST=127.0.0.1
DB_PORT=3306

    Verificación: Variables completas, host autorizado y directorios logs/public/media/public/static creados. FIELD_ENCRYPTION_KEY preservada; no incluir secretos en capturas.

  5. Conectar WSGI y Redis

    En passenger_wsgi.py enlazar la aplicación WSGI del proyecto. Configurar REDIS_URL con la conexión facilitada por el proveedor; usar TLS si la conexión es remota.

    from app_core.wsgi import application
# comprobación desde la terminal del virtualenv:
# python manage.py check_cache

    Verificación: Passenger puede importar application y check_cache confirma conexión; no usar LocMemCache como sustituto del control compartido en producción.

  6. Migrar y recoger recursos

    Ejecutar en el entorno activo. Si es primera instalación, crear personal autorizado y configurar TOTP mediante el flujo documentado.

    python manage.py migrate
python manage.py collectstatic --noinput
python manage.py showmigrations

    Verificación: Migraciones aplicadas marcadas [X]; collectstatic sin errores; recursos publicados accesibles.

  7. Proteger archivos y programar tareas

    Copiar reglas documentadas a media y a carpetas certificates, passport_images, signature_images y pqrs. Añadir cron sin duplicarlo y revisar seguridad.

    python manage.py crontab add
python manage.py check_cron
python manage.py check --deploy
python manage.py check_security
python manage.py check_requirements

    Verificación: Acceso directo a documento protegido devuelve 404; cron instalado; controles sin fallos bloqueantes ni advertencias de seguridad sin resolver.

  8. Publicar y comprobar

    Crear tmp si no existe, reiniciar Passenger y verificar aplicación por HTTPS. Ejecutar CP-01 a CP-04 como smoke test sobre datos autorizados de prueba; carga solo en entorno aislado. 

    mkdir -p tmp
touch tmp/restart.txt
python manage.py check_health --http

    Verificación: HTTP de salud correcto; BD, caché y correo operativos; estáticos visibles; acceso y aislamiento correctos. Registrar tag, fecha, ejecutor y capturas.

05c · Plan de reversión

  1. Contener: detener la publicación si fallan salud, migraciones, autorización o smoke tests; conservar logs y suspender escrituras.
  2. Restaurar: volver al commit/tag previo con sus dependencias y configuración. Si el esquema cambió de forma incompatible, restaurar la copia consistente de base y media; no revertir migraciones a ciegas.
  3. Verificar y reactivar: ejecutar collectstatic, reiniciar Passenger, validar salud, datos y acceso a certificados; registrar versión, duración e impacto antes de reabrir.

Manual de usuario · Muestra

Acceso y segundo factor

Ingrese por /account/login/. Si tiene TOTP, complete el código de la aplicación autenticadora. Para configurar el segundo factor use /account/two_factor/setup/ y conserve los códigos de recuperación. El panel exige personal autorizado con segundo factor verificado.

Orden de compra

El aprobador abre una orden autorizada y completa la etapa previa antes de avanzar. Tras guardar, comprueba estado, responsable y fecha en la línea de tiempo. Si se rechaza una transición, revisa el paso pendiente; no modifica directamente la base de datos.

Certificados

El tenedor consulta su historial y abre únicamente documentos propios. El verificador externo sigue el QR o enlace público, completa el código enviado a su correo cuando el flujo lo solicita y carga el archivo para contrastar su huella. Un archivo alterado no debe reconocerse como válido. Si falla la consulta, reporta el código de referencia sin adjuntar documentación sensible.

Los tiempos de validez de códigos se verifican contra la configuración desplegada: no se fija aquí un TTL a partir de antecedentes inconsistentes.
